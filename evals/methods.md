# 評価手法

## 有限モデルの代表 witness

`checkModel` の BFS で状態・遷移を探索する。モデルの状態同一性が正しくても、同じ状態へ戻る全履歴を列挙するわけではない。完全探索を実装の隠れた状態の網羅に読み替えない。[pilot](iterations/0000-pilot.md) で3回目のリトライと drop 無視を見逃すことを再現した。

## Uniform enabled walk

各状態の `actions()` から PRNG で1つ選び、1ケースの深さ上限まで続ける。ケースごとに初期状態から始める。初期状態と successor が一意で、有効操作が空にならないモデルを対象にする。seed、深さ上限、reset/step 予算を plan に記録する。

## State/edge novelty corpus

保存した prefix に1操作追加し、新しいモデル状態・遷移が出た prefix を保存する。モデル遷移の再計算を減らせる一方、SUT の reset と prefix の再生が増える。履歴に依存する故障はモデル状態の新規性だけでは誘導できない。Fest の因果順序の coverage やシナリオ誘導を再実装したものではない。

## PBT と縮小

raw-array は無効操作を棄却する。enabled-input は選択整数列から状態に応じた有効操作を生成し、縮小時にも操作列を再構築する。生成分布も異なるため、検出数の差を棄却削減だけに帰属させない。試行数、棄却、縮小、再確認を含む操作数を分け、seed/path に加えて操作列自体を保存する。

## 時計・並行履歴・SMT

時計の注入は期限への到達と再現を可能にする。Promise の制御は read/write の順序を変え、完了した操作の call/return 履歴を bounded checker で検査する。未完了操作やクラッシュをまたぐ履歴は扱わず、予算切れは `inconclusive`。SMT は同じ契約から入力を作るが、手書き境界値に対する追加検出と初期化・solve の費用を評価する。

## 共通の測り方

- 探索予算は reset を1、実行する step を1として数える。case ごとの深さが違っても予算を共有する。
- corpus の要求操作数と、最初の mismatch で打ち切られた実際の操作数を分ける。fault ごとの最初の検出までの操作数も保存する。
- witness の故障版・正常版での再確認は探索予算の外で行う。探索時間に再確認やファイル保存の費用を混ぜない。
- 最初の反例の長さは縮小前の診断コストの一指標。未検出の場合は0ではなく `null`。
- 同じ seed ごとの追加検出と後退、故障別の検出数、正常版の reset 数と実行時間を比較する。検出数が増えても費用や反例長が増えた場合は trade-off として扱う。
- `complete` は実験が正常に完了したこと。`assessment` は検出数だけの `improved / regressed / mixed / unchanged`。採用判断は iteration に理由とともに残す。

ケースは現時点で人工故障のカウンターが中心。実リポジトリの過去バグ・修正版の対照、モデルと Driver を作る人手、未知ケースへの効果は別の評価項目として残す。
