# 採用判断のための実験計画

2026-11-14。結果を見る前に比較条件を固定する。試作に存在する機能は、製品への採用が決定した機能とは分けて扱う。

目的は既存のテストに対して追加で有効な知見が得られるかを確認すること。まず故障を意図的に入れた独立した実装で、検出能力と盲点を調べる。既知故障の検出は実プロジェクトの未知バグ発見実績に数えない。

| 実験     | 比較                                                                         | 事前に固定する条件                                                                                  | 確認する価値                                                         |
| -------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 履歴探索 | BFS witness、uniform enabled walk、state/edge novelty corpus、fast-check PBT | seed 1〜20、操作数の上限8。walk/corpus は reset を含め512操作、PBT は64試行と縮小の実測コストを別記 | モデルの到達状態を覆うだけで見逃す実装の隠れた状態、探索の追加検出力 |
| 時刻境界 | 時刻を進めないケース、仮想時計と境界値、Z3 で同じ境界を生成                  | TTL 1〜10,000、経過時間0〜20,000、期限ちょうどの読み取り                                            | 必要な可制御性と、ソルバーを使う追加価値の切り分け                   |
| 並行履歴 | 逐次実行、read/write を制御した実行                                          | 2呼び出し・各2段階の有効な6順序、正常実装と lost-update 実装                                        | await を直列化したドライバーで覆えない故障                           |

故障集合は永続化漏れ、重複処理、3回目の同一 ID リトライ、配信順序の無視、drop の無視、期限判定の off-by-one、非同期 read-modify-write の lost update。正常実装を必ず対照にする。探索戦略には故障 ID、故障条件、正解の操作列を渡さない。

記録するもの:

- seed ごとの検出結果、正常実装の誤検出、無効入力、例外、未解決の区別。
- 最初の検出までの reset / step 数、試行数、実行時間。失敗は打ち切りとして扱い、未検出をゼロ時間の成功に置き換えない。
- 生成器・ソルバーの準備時間と実行時間。機械依存の時間値には合否の閾値を置かない。
- 原因を示す操作列・並行履歴、同じ故障の再現、正常版の通過。
- モデルの状態・遷移の到達数。カバレッジ増加をバグ検出数に代用しない。

比較可能性を限定する。同一操作予算の直接比較は walk と novelty corpus のみ。BFS は代表 witness の限界の確認、PBT は shrinking 込みの別のコストモデル。SMT と手書き境界値の比較では、同じ制約を人が与えていることを明記する。novelty corpus は Fest の再実装ではなく、モデルの状態・遷移を使う小さいアブレーションである。

判断は「この用途で使う」「実験を続ける」「追加価値が確認できるまで保留」。単一の人工例で全体の採用を決定しない。外的妥当性の次のゲートは、実リポジトリの固定した過去バグと正常版を使う再現実験、その後に修正を見ずに行う未知ケースの検査とする。

## 初回測定後の追加実験

初回の raw-array PBT で正常版の棄却が中央値132件になったため、状態から有効操作を選ぶ生成器を追加する。seed 1〜20、最大8操作、64試行、同じ故障集合を維持する。選択整数列を縮小し、その都度モデルから実行可能な操作列を再構築する。これは測定後に決めた探索的アブレーションとして区別し、uniform / novelty の比較条件は変更しない。
